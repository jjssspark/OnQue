# OnQue 프론트엔드 개편 설계 — R1 "층위 + 사이드 요약"

**날짜**: 2026-08-11
**범위**: 디자인 토큰 전역 교체 + 공용 UI 컴포넌트 신설 + 대시보드 레이아웃 개편
**제외**: 대시보드 외 9개 화면의 레이아웃 (토큰 교체 효과만 자동으로 받음)

---

## 왜 하는가

사용자가 지목한 불만 네 가지가 전부 같은 뿌리에서 나온다.

| 불만 | 지금 코드의 원인 |
|---|---|
| 밋밋함 / 템플릿 같음 | 모든 카드가 `rounded-2xl border border-border bg-surface p-5`로 동일 |
| 뭐가 중요한지 안 보임 | 모든 제목이 `text-sm font-bold`. 급한 건과 단순 목록이 같은 무게 |
| 배치·동선이 불편 | 카드가 세로로만 쌓임. 가로 공간을 요약에 쓰지 않음 |
| 버튼·입력 디테일 | 버튼 스타일이 각 파일에 클래스 문자열로 흩어져 있고 `:focus-visible` 처리가 없음 |

**하나의 원인**: 시각적 구분을 전부 "같은 테두리 + 같은 여백"에 맡기고 있다. 위계를 만들 수단(밝기 층위, 크기 대비, 색의 의미)을 하나도 안 쓴다.

## 방향 — R1

시안 6개(A~F, R1~R3)를 목업으로 비교해 선택했다. 선택된 R1의 규칙:

1. **테두리가 아니라 밝기로 나눈다** — 배경 → 카드 → 침강면(sunken)이 3단으로 떨어진다
2. **색은 상태에만 쓴다** — 기한 지남(코랄), 마감 임박(앰버), 그 외 무채색. 장식용 색을 쓰지 않는다
3. **가로를 쓴다** — 오른쪽 좁은 열에 숫자·일정을 몰아 본류가 세로로 늘어나지 않게 한다
4. **평소엔 조용하고, 손을 대면 반응한다** — 카드에 포커스가 가야 액션 버튼이 펼쳐진다

## 1. 디자인 토큰

`onque-frontend/app/globals.css`의 `:root`와 `@theme inline`을 교체한다.

```css
:root {
  /* 표면 3단 — R1의 핵심. 선이 아니라 밝기 차로 구역을 나눈다 */
  --background:       #07080e;   /* 앱 배경. 기존 #0a0c12보다 어둡게 해 카드가 떠 보이게 */
  --surface:          #12151f;   /* 카드 */
  --surface-sunken:   #0c0e16;   /* 사이드 요약. 카드보다 어두워 뒤로 물러난다 */
  --surface-hover:    #171b28;   /* 카드 hover */
  --sidebar:          #04050a;

  /* 글자 3등급. 모두 --surface 위에서 4.5:1을 넘긴다(아래 계산 참고) */
  --foreground:       #e8eaf4;   /* 본문·제목 */
  --fg-muted:         #a8aec5;   /* 보조 본문        8.3:1 */
  --fg-dim:           #868da8;   /* 라벨·캡션        5.5:1 */
  --fg-disabled:      #6f7590;   /* 비활성·장식 전용  4.0:1 — 읽어야 하는 글자에 쓰지 않는다 */

  --brand:            #7c8cff;   /* 인디고. 기존 #6183ff에서 한 단계 */
  --brand-foreground: #06070d;

  /* 상태색. 기존 --accent(#f0954a)는 --soon으로 흡수된다 */
  --late:             #ff6b5e;
  --late-bg:          #ff6b5e22;
  --late-fg:          #ff9c92;
  --soon:             #f5a623;
  --soon-bg:          #f5a62322;
  --soon-fg:          #f7c173;

  --hairline:         #ffffff0d;  /* 선이 꼭 필요한 곳만 */
  --border:           #171a24;    /* 기존 #262a3a에서 약화 — 아래 "왜 안 지우는가" 참고 */
}
```

### `--border`를 지우지 않는 이유

R1은 테두리를 안 쓰지만, **대시보드를 제외한 9개 화면이 전부 `border-border`에 의존해 구조를 만들고 있다.** 토큰을 지우면 그 화면들이 한 덩어리로 뭉개진다. 값만 약화시켜, 개편하지 않은 화면은 희미한 테두리 + 새 밝기 대비로 자연스럽게 넘어가게 한다. 화면별 레이아웃 개편이 끝나면 그때 제거한다.

### `--accent` 처리

기존 `--accent: #f0954a`는 `SmartDashboardPanel`, `CommitmentPanel` 등에서 쓰인다. `--soon`(#f5a623)으로 흡수하되, **`--accent`를 `var(--soon)`의 별칭으로 남긴다.** 기존 참조를 한 번에 다 고치지 않아도 깨지지 않는다.

### 대비 계산 (WCAG 2.1, `--surface` #12151f 기준)

| 토큰 | 값 | 대비 | 판정 |
|---|---|---|---|
| `--foreground` | #e8eaf4 | 14.6:1 | 통과 |
| `--fg-muted` | #a8aec5 | 8.3:1 | 통과 |
| `--fg-dim` | #868da8 | 5.5:1 | 통과 |
| `--fg-disabled` | #6f7590 | 4.0:1 | **본문 사용 금지** |
| `--brand` | #7c8cff | 6.1:1 | 통과 |
| `--late-fg` | #ff9c92 | 9.0:1 | 통과 |
| `--soon-fg` | #f7c173 | 11.1:1 | 통과 |

목업 단계에서 캡션에 `#6f7590`을 쓰고 있었는데 계산해 보니 4.0:1로 미달이었다. 그래서 글자를 3등급으로 나누고 캡션을 `--fg-dim`(5.5:1)으로 올렸다. `#6f7590`은 비활성 상태와 장식 요소에만 남긴다.

## 2. 공용 UI 컴포넌트

`onque-frontend/components/ui/`에 새로 만든다. 프로젝트 구조 규약상 `components/ui/`는 도메인 용어를 모르는 순수 UI 계층이다.

지금은 카드·버튼 스타일이 각 화면 파일에 클래스 문자열로 흩어져 있어, 한 번 바꾸려면 10곳을 고쳐야 한다.

### `Surface.tsx`

```tsx
type Props = {
  level?: 'card' | 'sunken';   // 기본 'card'
  interactive?: boolean;        // hover 시 떠오름
  children: ReactNode;
  className?: string;
};
```

- `card` → `bg-surface`
- `sunken` → `bg-surface-sunken`
- `interactive` → `hover:-translate-y-[3px] hover:bg-surface-hover`, `transition` 280ms `cubic-bezier(.16,1,.3,1)`

### `Button.tsx`

```tsx
type Props = {
  variant?: 'primary' | 'ghost';   // 기본 'primary'
  size?: 'sm' | 'md';              // 기본 'md'
} & ButtonHTMLAttributes<HTMLButtonElement>;
```

- `primary` → `bg-brand text-brand-foreground`, `hover:brightness-110`
- `ghost` → `bg-white/10 text-fg-muted`
- 공통: `active:scale-[.96]`, **`focus-visible:ring-2 focus-visible:ring-brand focus-visible:ring-offset-2 focus-visible:ring-offset-background`**

`focus-visible` 링은 필수다. 지금 코드에는 포커스 표시가 아예 없어 키보드 사용자가 어디에 있는지 알 수 없다.

### `StatusChip.tsx`

```tsx
type Props = { tone: 'late' | 'soon' | 'neutral'; children: ReactNode };
```

**색만으로 상태를 구분하지 않는다.** 항상 글자를 함께 넣는다(`1일 지남`, `D-3`). 색각 이상 사용자와 흑백 출력에서 정보가 사라지지 않게 한다.

## 3. 대시보드 레이아웃

`app/dashboard/page.tsx`를 재배치한다.

```
┌─사이드바 264─┬─────본류 1fr──────────────┬──요약 260──┐
│              │ 오늘 할 일 · 8월 11일 화    │            │
│  대시보드     │                           │  1 기한 지남 │
│  통화 요약    │ ┌ 급한 순 카드 스트림 ┐    │  3 열린 할일 │
│  문서 요약    │ │  A사 시안 (1일 지남) │    │ ────────── │
│  팀 채팅      │ │  B사 계약서 (D-3)   │    │ 다가오는 일정│
│  …           │ │  가격표 초안        │    │ 최근 요약 3건│
│              │ └───────────────────┘    │            │
│              │ 모듈 바로가기 · 클라이언트   │            │
└──────────────┴──────────────────────────┴────────────┘
```

### 블록 재배치

| 기존 블록 | 이동 후 |
|---|---|
| `CommitmentPanel` (약속) | **본류 스트림에 합류** |
| 우선 처리할 일 (할 일) | **본류 스트림에 합류** |
| `MetricStrip` (숫자) | 요약 열 상단. **대시보드가 넘기는 `metrics` 배열을 개수 그대로 세로로 쌓는다** — 지표 개수가 바뀌어도 레이아웃이 안 깨진다. `alert: true`인 지표는 `--late` 색 |
| 다가오는 일정 | 요약 열 |
| 최근 요약 | 요약 열 |
| `ClientPanel` (클라이언트) | **하단**, 모듈 바로가기 옆 |
| 모듈 바로가기 | 하단 유지, 스타일만 |

### 본류 스트림 정렬

약속과 할 일을 **종류가 아니라 급한 순으로** 하나의 목록에 섞는다. 정렬 키:

1. 기한이 지난 것 (많이 지난 것 먼저)
2. 마감 임박인 것 (기한 가까운 순)
3. 기한이 있는 나머지 (기한 순)
4. 기한 없는 것 (최근 등록 순)

각 항목에는 출처(`약속 · 통화` / `할 일`)를 라벨로 붙여, 섞여도 무엇인지 알 수 있게 한다.

"며칠 지났는지"는 백엔드 비서 컨텍스트에만 있고 `GET /commitments` 응답에는 없다. 프론트에서 `due_date`와 오늘 날짜로 계산한다 — **백엔드 API는 이 개편에서 건드리지 않는다.**

### 반응형

| 폭 | 배치 |
|---|---|
| ≥1280px | 본류 + 요약 2열 |
| 1024–1279px | 본류 + 요약 2열 (요약 220px로 축소) |
| <1024px | 요약이 본류 **위로** 이동, 숫자 2개가 가로로 나란히 |
| <768px | 사이드바 → 기존 `MobileNav`, 요약은 숫자만 (일정·최근요약은 접힘) |

## 4. 상호작용

### 카드

- `hover` / `focus-within` → `translateY(-3px)`, 배경 `--surface-hover`, 액션 버튼 펼침
- 기한 지난 항목 → 코랄 점 맥동 2.2s, 배경에 코랄 기미(`linear-gradient(101deg, #241318, #12151f 58%)`)

### 액션 버튼 노출 — 접근성 함정

목업에서는 버튼이 `:hover`에서만 나타났다. **그대로 만들면 터치 기기와 키보드에서 버튼을 쓸 수 없다.** 세 갈래로 처리한다.

```css
/* 1. 키보드: 카드 안 요소에 포커스가 가면 펼친다 */
.card:hover .actions,
.card:focus-within .actions { max-height: 44px; opacity: 1; }

/* 2. 터치: hover가 없는 기기에서는 항상 펼쳐둔다 */
@media (pointer: coarse) {
  .actions { max-height: none; opacity: 1; }
}

/* 3. 모션 최소화: 전역 차단이 transition을 죽이므로 즉시 보이게 한다 */
@media (prefers-reduced-motion: reduce) {
  .actions { max-height: none; opacity: 1; }
}
```

3번이 특히 중요하다. `globals.css`에 이미 `prefers-reduced-motion`에서 모든 `transition-duration`을 `0.01ms`로 죽이는 전역 규칙이 있다. 펼침을 `max-height` 전환에만 맡기면, 모션을 끈 사용자에게는 버튼이 **영영 안 열리거나 깜빡이며 열린다.**

### 모션 성능

`transform`과 `opacity`, `background-color`만 애니메이션한다. `max-height`는 레이아웃을 건드리지만 카드 하나당 44px 고정이고 동시에 하나만 열리므로 허용한다.

## 5. 구현 순서

각 단계는 그 자체로 빌드가 통과해야 한다.

1. **토큰 교체** — `globals.css`. `--accent`를 `--soon` 별칭으로 남겨 기존 참조를 살린다
   → 검증: `npm run build` 통과, 10개 화면이 새 색으로 뜨고 읽을 수 있다
2. **공용 컴포넌트 3개** — `Surface`, `Button`, `StatusChip`
   → 검증: 타입 에러 0. Storybook이 없으므로 대시보드에서 실제 사용해 확인
3. **대시보드 본류 스트림** — 약속+할일 병합·정렬, 카드 상호작용
   → 검증: 급한 순으로 정렬됨, Tab으로 모든 액션 도달
4. **요약 열** — 숫자·일정·최근요약 이동
   → 검증: 1280/1024/768/320에서 가로 스크롤 없음
5. **하단 재배치** — `ClientPanel` + 모듈 바로가기
   → 검증: 클라이언트 데이터가 여전히 보이고 링크가 동작한다

- [ ] 본문·라벨 대비 4.5:1 이상 (위 표의 값을 실제 렌더 결과에서 재확인)
- [ ] 백엔드 pytest 241개 통과 (무관하지만 회귀 확인)
- [ ] 대시보드 외 9개 화면이 깨지지 않고 읽을 수 있다

## 7. 이 개편에서 하지 않는 것

- **백엔드 API 변경** — "며칠 지났는지"는 프론트에서 계산한다
- **대시보드 외 화면의 레이아웃** — 토큰 교체 효과만 받는다
- **`--border` 토큰 제거** — 다른 화면이 의존 중이라 값만 약화시킨다
- **다크/라이트 테마 전환** — 다크 단일 유지. 로그인→앱 전환에서 화면이 튀지 않게 다크로 통일한 기존 결정을 지킨다
- **아이콘 교체** — 현재 SVG path 유지. 이모지는 쓰지 않는다

## 부록: 검토한 대안

시안을 세 차례 냈고, 사용자가 고른 경로는 **A~F 1차 전부 반려 → D 선택 → R1 선택**이다.
아래는 사용자가 실제로 말한 것과, 내가 붙인 해석을 구분해 적은 것이다.

| 라운드 | 안 | 결과 | 사용자가 말한 것 |
|---|---|---|---|
| 1차 | A 에디토리얼 / B 벤토 / C 스위스(라이트) | 셋 다 반려 | "다른 걸로 줘. 좀 더 반응형… 재밌어보이는… 그러나 직관적인" |
| 2차 | D 살아있는 보드 / E 젤리 팝 / F 하루 타임라인 | **D 선택** | "D로 가되, 디자인 및 배치, 색을 좀 더 개선할 수 없나?" |
| 3차 | R1 층위+사이드 / R2 지금·이번주·나중 / R3 온도 스펙트럼 | **R1 선택** | "R1으로 가자 그냥" |

**E·F, R2·R3의 개별 반려 사유는 사용자가 말하지 않았다.** 1차 반려 사유만 명시적이다 —
"반응이 없고 재미가 없다". 이 피드백이 2·3차 시안의 공통 전제(hover 반응, 맥동, 버튼 펼침)가 됐고,
D 계열 셋은 그 전제를 공유한 채 색·배치만 달랐다.

참고용으로 남기는 각 안의 성격(내 판단이며, 사용자 발언이 아님):

| 안 | 성격 | 이 프로젝트에서 걸리는 점 |
|---|---|---|
| A 에디토리얼 | 급한 한 건을 헤드라인처럼 크게 | 급한 건이 없는 날 화면 위쪽이 빈다 |
