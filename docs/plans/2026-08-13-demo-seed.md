# 시연용 시드 스크립트 구현 계획


**Goal:** 시연 때마다 대시보드를 같은 상태로 되돌리는 시드 스크립트를 만든다 — 콘텐츠만 갈아끼우고 팀원은 건드리지 않으며, Gemini를 부르지 않는다.

**Architecture:** 순수 데이터 생성(`build_demo_data`), 삭제(`clear_demo_content`), 삽입 조합(`seed_demo`), CLI(`main`) 네 층으로 나눈다. 앞의 셋은 세션을 인자로 받아 테스트에서 인메모리 DB로 검증할 수 있게 한다. CLI만 실제 `SessionLocal`을 만든다.

**Tech Stack:** Python 3, SQLAlchemy 2.0 스타일(`select`/`delete`), pytest, argparse

## Global Constraints

- 설계 근거는 `docs/specs/2026-08-13-demo-seed-design.md`. 충돌하면 스펙이 우선한다.
- **Gemini를 호출하지 않는다.** 요약 결과는 미리 작성한 텍스트를 DB에 직접 넣는다.
- **사용자·그룹 멤버십·그룹·초대 기록을 지우지 않는다.** 지우는 것은 약속·할 일·일정·요약·클라이언트뿐이다.
- 삭제는 항상 `group_id = <대상>`으로 한정한다. 다른 그룹 데이터를 건드리지 않는다.
- 삭제 순서는 참조 역순이다. `commitments.client_id`가 `clients`를 참조하므로 약속을 클라이언트보다 먼저 지운다.
- 모든 날짜는 인자로 받은 `today` 기준 상대 계산이다. 절대 날짜를 코드에 박지 않는다.
- 애플리케이션 코드(`main.py`, `routers/`, `models.py`, `gemini_service.py`)를 수정하지 않는다. 기존 백엔드 테스트 241개는 그대로 통과해야 한다.
- 작업 디렉터리는 저장소 루트 `/Users/tina/Project/OnQue`. 파이썬은 `venv/bin/python`을 쓴다.
- 커밋 메시지는 한국어, `<type>: <설명>` 형식.

## 파일 구조

**신규 생성**

| 파일 | 책임 |
|---|---|
| `scripts/__init__.py` | 빈 파일. `tests/`에서 `scripts.seed_demo`를 import 하기 위한 패키지 표시 |
| `scripts/seed_demo.py` | 데이터 정의 · 삭제 · 삽입 · CLI |
| `tests/test_seed_demo.py` | 위 함수들의 검증 |

`scripts/seed_demo.py` 한 파일에 네 층을 모두 둔다. 200줄 안쪽이고 함께 변경되는 코드라 나눌 이유가 없다.

**기존 코드에서 쓰는 것 (수정하지 않는다)**

- `models.py` — `Client`, `Commitment`, `Document`, `Schedule`, `Todo`
- `db.py` — `SessionLocal` (CLI에서만)
- `tests/conftest.py` — `db_session` 픽스처 (인메모리 SQLite, `client` 픽스처에 의존)

**확인된 스키마 (그대로 쓴다)**

| 모델 | 필수 필드 |
|---|---|
| `Client` | `group_id`, `name` |
| `Commitment` | `group_id`, `content`, `status`, `source_type`, `evidence` (전부 NOT NULL) / 선택: `client_id`, `due_date`, `created_at` |
| `Todo` | `group_id`, `content` / 선택: `due_date`, `is_done`, `created_at` |
| `Schedule` | `title`, `scheduled_date` / 선택: `group_id` |
| `Document` | `source_type`, `category`, `filename`, `summary` / 선택: `group_id`, `is_template`, `created_at` |

`Document.category`의 유효값은 `기획`·`디자인`·`개발`·`마케팅`·`기타`다 (`gemini_service.classify_document_category`).

```python
def count_demo_content(session, group_id: int) -> dict[str, int]:
    """지울 대상 건수를 테이블별로 센다. 실행 전 사용자에게 보여주는 용도다."""

        model.__tablename__: session.scalar(
            select(func.count()).select_from(model).where(model.group_id == group_id)
        )
        for model in CONTENT_MODELS
    }


def clear_demo_content(session, group_id: int) -> dict[str, int]:
    """대상 그룹의 콘텐츠만 지운다.

    사용자·그룹 멤버십·그룹·초대 기록은 건드리지 않는다. 시연 팀에는 초대로

    커밋하지 않는다. 호출자가 삽입까지 한 트랜잭션으로 묶는다.
    """

    for model in CONTENT_MODELS:
        result = session.execute(delete(model).where(model.group_id == group_id))
        deleted[model.__tablename__] = result.rowcount
```

```python
def seed_demo(session, group_id: int, today: date) -> dict[str, int]:
    """대상 그룹의 콘텐츠를 지우고 데모 데이터로 채운다.

    커밋하지 않는다. 호출자가 커밋한다 - 삭제와 삽입이 한 트랜잭션이어야
    중간에 실패했을 때 반쯤 지워진 상태로 남지 않는다.
    """
    clear_demo_content(session, group_id)
    data = build_demo_data(today)

    clients = [Client(group_id=group_id, name=name) for name in data.clients]
    session.add_all(clients)
    session.flush()  # client_id를 얻어야 약속을 연결할 수 있다
    client_ids = [c.id for c in clients]

    for row in data.documents:
        session.add(Document(group_id=group_id, is_template=False, **row))

    for row in data.commitments:
        index = row["client_index"]
        session.add(
            Commitment(
                group_id=group_id,
                client_id=None if index is None else client_ids[index],
                content=row["content"],
                due_date=row["due_date"],
                status=row["status"],
                source_type=row["source_type"],
                evidence=row["evidence"],
                created_at=row["created_at"],
            )
        )

    for row in data.todos:
        session.add(Todo(group_id=group_id, **row))

    for row in data.schedules:
        session.add(Schedule(group_id=group_id, **row))

    session.flush()
    return count_demo_content(session, group_id)
```

**해결한 불일치**

- 스펙 본문은 "약속 7 + 할 일 6 = 13건"이라 적었는데 이는 **열린 항목** 기준이다. 계획의 데이터는 종료된 약속 2건과 완료된 할 일 2건을 더해 총 17건을 넣는다. 걸러지는 것을 시연으로 보이려면 데이터에는 있어야 하고, 스펙의 표에도 그 항목들이 명시돼 있다. 모순이 아니라 세는 기준의 차이다.
- 스펙은 시드 위치를 `scripts/`로 정했으나 거기서 저장소 루트의 `models`를 import 할 방법을 정하지 않았다. Task 1에서 `sys.path.insert`로 해결하고, 테스트가 `scripts.seed_demo`를 import 할 수 있도록 `scripts/__init__.py`를 함께 만든다.
- `Schedule.group_id`와 `Document.group_id`는 nullable이다. `delete(...).where(model.group_id == group_id)`는 NULL 행을 건드리지 않으므로, 그룹에 속하지 않은 기존 일정·문서는 안전하다.

**타입 일관성**

`build_demo_data`가 돌려주는 dict의 키가 Task 3의 모델 생성자 인자와 맞는다 — `documents`·`todos`·`schedules`는 `**row`로 그대로 펼치고, `commitments`만 `client_index`가 모델에 없는 필드라 명시적으로 변환한다. `count_demo_content`가 돌려주는 키는 `__tablename__`(`commitments`·`todos`·`schedules`·`documents`·`clients`)이며 Task 2·3·4의 단언과 출력이 같은 키를 쓴다.
