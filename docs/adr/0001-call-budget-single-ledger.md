# ADR-0001 · AI 호출 예산을 장부 하나로 관리하고 소비자별 상한을 다르게 둔다

- 상태: 채택
- 날짜: 2026-08-17
- 출처: `docs/specs/2026-08-17-ai-call-budget-design.md`

## 맥락

Gemini 무료 티어의 `gemini-2.5-flash`는 하루 20건까지만 부를 수 있다. 사용자 요청
(요약·비서·채팅)과 백그라운드 정리 작업이 같은 한도를 나눠 쓴다. 배분 규칙이 없으면
백그라운드가 20건을 다 먹은 날 사용자는 아무것도 못 한다.

## 결정

장부 테이블 하나에 총 사용량만 기록하고, 소비자마다 멈추는 지점을 다르게 둔다.

```
user  : calls < DAILY_TOTAL            (20)
sweep : calls < DAILY_TOTAL - RESERVE  (8)
```

```
잔량 20 ────────────────────────────── 0
        │  스윕이 도는 구간  │   예비선=12   │
사용자  │●●●●●●●● 쓸 수 있음 ●●●●●●●●●●●●●│
스윕    │●●●●●●●●│      멈춤            │
```

## 버린 대안

**장부 2개로 고정 분할.** 스윕이 3건만 쓴 날에도 사용자가 12건에서 막힌다. 남는 몫을
쓸 방법이 없다.

**양쪽 최소 보장 + 공유 구간.** 상태가 셋으로 늘면서 경계값 조합이 6지점이 되고,
사용자가 잔량을 예측하기 어려워진다.

## 이유

기존 코드에 이미 적혀 있던 원칙을 규칙으로 옮긴 것이다.

> 시킨 일이 안 시킨 일 때문에 실패하는 것이 한도 자체보다 나쁘다.
> (`commitment_service.py:196`)

## 결과

`sweep_budget` 테이블을 `call_budget`으로 개명했다. 의미가 "스윕이 쓴 수"에서
"전체 소비"로 바뀌는데 이름을 두면 거짓말이 된다. 이관 스크립트를 함께 뒀다.
