# ADR-0003 · 예산 검사를 필수 키워드 인자로 강제한다

- 상태: 채택
- 날짜: 2026-08-17
- 출처: `docs/specs/2026-08-17-ai-call-budget-design.md`

## 맥락

`gemini_service`에 `generate_content` 호출이 9군데 있다. 앞으로 새 경로가 추가될 때
예산 검사를 빠뜨리는 것을 막아야 한다.

`gemini_service`는 DB를 모르는 계층이라 세션을 넘길 수 없다.

## 결정

각 공개 함수가 `claim: Callable[[], bool]`을 필수 키워드 인자로 받는다.
빠뜨리면 `TypeError`로 즉시 터진다.

```
라우터
  └ gemini_service.chat_reply_with_actions(claim=call_budget.user_claimer(), …)
        └ 래퍼: claim()  ──▶ 별도 세션 → 조건부 UPDATE → 커밋 → 닫기
                 ├ False ─▶ QuotaExceeded
                 └ True  ─▶ generate_content
```

## 버린 대안

**전역 등록 방식(`set_budget_manager`).** 호출부를 하나도 안 고쳐도 되지만 전역 상태가
생기고 테스트 격리가 깨진다.

## 이유

같은 실수를 이미 한 번 했다(TS-035). 기준 날짜를 넣어주는 함수를 호출부 여섯 곳 중
두 곳에 빠뜨렸는데, 선택적 인자라 조용히 넘어갔다. 테스트 265개가 전부 통과하는 상태로
마감일이 799일 어긋난 채 시연 직전까지 갔다.

선택적이면 빠뜨려도 돌아간다. 필수면 빠뜨린 순간 터진다.

## 결과 — 이 결정만으로는 부족했다

나중에 확인해 보니 호출부에서 `claim=`을 지워도 테스트 315개가 그대로 통과했다.
테스트 스텁 25개에 붙여둔 `**kwargs`가 인자 누락을 통째로 삼키고 있었다.

즉 "빠뜨리면 터진다"는 보장이 CI가 아니라 프로덕션 런타임에서만 작동하고 있었다.
스텁에서 `**kwargs`를 걷어내 닫았다(TS-036).

언어 수준의 강제만으로는 부족하고, 그 강제가 테스트 환경에서도 살아 있는지를 따로
확인해야 한다.
